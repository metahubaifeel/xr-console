## 2. 三个必记的坑（踩过）

### ① `/ex001/joint_states` 的 `lift_joint` 是**陈旧值**（一直 0.772）
真实升降读 **`/lift/joint_states`**；控制升降发 `/lift_position_controller/commands`（Float64MultiArray）。

### ② 「停」≠「归零」
```
停   = POST /stop      controller 回 mode 1，臂【冻结在当前姿态】
归零 = zero_arm        臂扫回竖直下垂，夹着东西会被带走、扫过桌面
```
`编排.py` 收尾以前无条件归零 —— 抓到枪后一归零，枪被扫过银框，看起来像「放进银框了」。
现在用 `--hold`：收尾只停会话、不归零。

### ③ harness 的「会话」≠ client 的会话
`/api/session/start` **不会启动 client**，它只启动 harness 自己的 step 状态机并把 prompt 写进 client。
**必须先让 client 处于 mode 6（激活）**：

```bash
python3 tools/编排.py --flow tools/grasp_only.json --hold &          # 先起 client
curl -X POST http://127.0.0.1:8910/api/session/start \
     -H 'Content-Type: application/json' -d '{"auto_monitor":false}'  # 再让 harness 接管
```

## 5. 工具（`tools/`）

| 文件 | 作用 |
|---|---|
| `关节.py` | **单关节按度数控制**（`motor_control.py`），±0.3°。`catalog / read / move / pose / grip / both-zero` |
| `对准.py` | 抓枪后对准闭环：**A** 夹持稳定判据 / **B** 转手腕直到扫到 / **C** 放弃 |
| `判读.py` | 独立 GPT 视觉判读（**只读不动，不在控制回路里**） |
| `cam_srv.py` | 三路相机 HTTP 服务（`:8895`） |
| `grab3.sh` | 一条命令抓 head/chest/bev → `/tmp/v_*.jpg` |
| `编排.py` | 开环时间轴编排器，`--edit` 有 `--hold` |
| `grasp_only.json` | 只抓扫码枪的单步流程 |
| `site/` | 现场版 `底盘.py` `锁臂.py` `扫码枪.py` `robot_api.py` `scan_rules.json` `hg2.py` `flows/` |

常用命令：
```bash
python3 tools/关节.py read                          # 读真实关节角度
python3 tools/关节.py move left_arm_joint2 45       # 绝对角度
python3 tools/关节.py move left_arm_joint6 -20 --rel
python3 tools/关节.py grip left 120                 # 夹爪
python3 tools/关节.py both-zero                     # 【仅调试】逐关节回零
bash tools/grab3.sh                                 # 三路图
python3 tools/判读.py --q "机器人是否夹住扫码枪"      # GPT 判读
python3 tools/对准.py --check-grasp                 # 只跑判据 A（25s）
```

**单关节控制是「遥控」，比赛时违规** —— 只用于调试和姿态标定。比赛走 VLA。
