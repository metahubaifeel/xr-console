# 现场联调记录 · 2026-11-28 · 量子1号 Pro（ex001）

本文件记录在真机上把 `wft/harness` 跑通时改的四处**环境适配**，以及新增的工具。
骨架（engine / adapters / prompts / 前端 / 7 步流程）全部来自 `wft/harness`，业务逻辑未改动。

## 一、四处环境适配（必须保留，否则跑不起来）

### 1. 控制台 `_exec` 走 SSH，不走 Portainer
- **现象**：`/motors`、`/arm-lock`、`/capabilities` 全返回 `HTTP Error 403: Forbidden`
- **原因**：Portainer（`:9000`）的 exec 接口在比赛网络下被拒
- **改法**：`控制台.py` 的 `_exec()` 在 `SSH_USER` 存在时用
  `sshpass -p $SSH_PASSWORD ssh` 连 `xr@<机器人>`；`BatchMode=yes` 改 `no`，
  显式 `PreferredAuthentications=password`、`PubkeyAuthentication=no`

```bash
ROBOT_SSH_USER=xr SSH_PASSWORD=<密码> python3 控制台.py --ip <机器人IP> --port 8900 --host 0.0.0.0
```

### 2. `_loose_json()`：从混有日志行的输出里取 JSON
- **现象**：`/motors` 返回 `Expecting value: line 1 column 2 (char 1)`
- **原因**：`motor_control.py` / `bridge.py` 的 `[robot_io] INFO` 日志混进 stdout，
  原来的 `.splitlines()[-1]` 拿到日志行
- **改法**：新增 `_loose_json(raw, tag)`，取**最后一个以 `{` 开头且 `}` 结尾**的行；
  `harness_bridge()` 的**所有** operation 都走它（原来只有 `motor-` 分支）

### 3. `cam_srv.py`：三路相机 + 别名（腕部话题已不是 JPEG）
- **现象**：`/snap?d=wa` 全 404；`adapters.camera()` 的
  `raw.startswith(b'\xff\xd8')` 校验不过 → `observe()` 抛异常 →
  `/api/session/start` 返回 `backend operation failed`
- **原因**：腕部相机话题从 JPEG 变成 h26x 编码，不是 JPEG 流
- **改法**：`tools/cam_srv.py` 用 rclpy 常驻订阅三路压缩图并起 HTTP（`:8895`）：

```
/camera_head_front/color/image_raw/compressed    → head
/camera_chest_front/color/image_raw/compressed   → chest
/camera_chassis_front/color/image_raw/compressed → bev
别名：8→head  wa/wb→chest  0/6→bev
```

harness 侧新增 `XR_CAM_URL`（`harness/config.py` + `adapters.camera()`），
相机请求直连 `:8895`，绕开控制台的 `/snap` 转发。

### 4. `reasoning` 参数按模型条件化
- **现象**：GPT 调用返回 `HTTP 400`
- **原因**：`gpt-4.1` 等非推理模型不接受 `reasoning: {effort: none}`
- **改法**：
```python
if model.startswith('o') or 'gpt-5' in model or 'gpt-6' in model:
    payload['reasoning'] = {'effort': 'none'}
```
`gpt-6.1-terra` 实测判读质量好。超时 40s → 120s（6 张 high-detail 图）。

## 三、三个必须记住的坑

1. **`/ex001/joint_states` 的 `lift_joint` 是陈旧值**（一直 0.772）。
   真实升降读 `/lift/joint_states`。
2. **「停」≠「归零」。** 停 = `POST /stop`，controller 回 mode 1，**臂冻结在当前姿态**；
   归零 = `zero_arm`，臂扫回竖直下垂，**夹着东西会被带走、扫过桌面**。
   `编排.py` 收尾原来无条件归零是错的，已加 `--hold`。
3. **harness 的「会话」≠ client 的会话。** `/api/session/start` 只启动 harness 自己的
   step 状态机并把 prompt 写进 client，**它不会启动 client**。必须先让 client 处于
   mode 6（激活），harness 才能驱动：

```bash
python3 tools/编排.py --flow tools/grasp_only.json --hold &   # 先起 client
curl -X POST http://127.0.0.1:8910/api/session/start -d '{"auto_monitor":false}'   # 再让 harness 接管
```
